# 仪表轨道与语音反馈设计

> 状态：用户已确认视觉方向，待书面规格审阅
> 页面：`/dashboard`

## 1. 目标

把单圆环境仪表升级为同时展示温度、湿度和光照的三圆轨道，并让用户通过点击换位与指针视差感受到立体层次。同时明确语音按钮的点击方式，以及当前指令由本地规则还是 StepFun 解析。

## 2. 三圆轨道

- 中央主圆显示当前选中指标，桌面直径约 300px。
- 左右两个副圆同时显示另外两个指标，桌面直径约 150px。
- 三个圆始终包含数值、单位和指标名；副圆减少装饰密度，但不隐藏数据。
- 点击任一副圆后，它沿弧形轨迹放大进入中央；原主圆缩小并移动到对应侧边。
- 底部温度、湿度、光照分段按钮继续保留，点击后触发同样的换位，支持键盘操作。
- 默认中央指标为温度；指标顺序固定为温度、湿度、光照，避免每次换位后空间关系不可预测。

## 3. 3D 交互

- 使用 CSS `perspective`、`rotateX`、`rotateY`、分层阴影和径向高光构建立体圆面。
- 指针在仪表区域内移动时，三个圆共享轻微视差；主圆最大倾角不超过 7 度，副圆不超过 4 度。
- Framer Motion 负责圆的位置、尺寸、透明度和层级换位，不新增 Three.js 场景。
- 高光颜色跟随指标：温度偏暖金、湿度偏青绿、光照偏月白。
- 数据刷新只更新数值与进度弧，不触发圆的位置变化。
- `prefers-reduced-motion` 下关闭倾斜、轨道弹性和持续旋转，仅保留短淡入淡出。

## 4. 响应式

- 桌面：主圆约 300px，副圆约 150px，三圆横向覆盖约 600px。
- 窄屏：主圆约 236px，副圆约 92px，副圆部分靠近主圆但不遮挡数值。
- 三圆区域使用固定比例和最小高度，切换、加载与长数值不得造成页面跳动。
- 触控设备不依赖 hover；点击副圆和底部分段按钮都可完成切换。

## 5. 数据语义

- 温度、湿度来自 RDK X5 DHT11 实测。
- 光照没有传感器时继续展示估算值，并保留页面现有“光照为灯态估算”提示。
- 硬件离线时三个圆显示 `--`，不得回填模拟数据并标成实测。
- stale 数据继续显示数值，同时保留“正在显示最后有效读数”状态。

## 6. 语音按钮

- 交互固定为“单击开始，再次单击停止”，不使用长按。
- 默认文案为“点击说话”；监听时为“正在聆听，再次点击可停止”。
- 浏览器识别到完整语音后自动停止，并把文本提交给 `/api/voice/parse`。
- 浏览器不支持语音识别时自动展开文字输入，不让按钮表现成不可用。
- 请求执行期间禁用重复提交，并显示“正在执行”。

## 7. 指令来源反馈

- API 已返回 `mode: "hardcoded" | "natural"`，前端在执行结果旁显示来源。
- `hardcoded` 显示“本地指令”，用于关灯、开灯、开夜灯、调高温度等固定指令。
- `natural` 且模型成功返回时显示“StepFun 智能理解”。
- StepFun 未配置、超时或响应无效时显示“模型未配置或暂不可用”，并保留现有可尝试指令提示。
- 不在浏览器或前端暴露 `STEPFUN_API_KEY`。

## 8. 文件边界

- `components/EnvGauge.tsx`：三圆轨道、指标切换和指针视差。
- `components/VoiceInput.tsx`：监听文案、再次点击停止和指令来源标签。
- `app/globals.css`：减少动态偏好和必要的仪表动画样式。
- 不修改硬件 API、DHT11 服务、LED Pin 映射或 StepFun 服务端解析逻辑。

## 9. 测试与验收

- 单元测试三指标排序、点击换位、数值格式和离线占位。
- 单元测试语音结果对 `hardcoded`、`natural`、fallback 三种来源的展示。
- TypeScript、现有 Vitest 和生产构建必须通过。
- 桌面 1115x837 与移动端 390x844 截图中，三圆不得重叠文字或超出容器。
- 鼠标移动时圆面有轻微立体倾斜；开启减少动态偏好后不持续运动。
- 快捷指令“关灯”仍能控制真实 RDK X5；自然语言只有配置 Key 后才能标记为 StepFun。
